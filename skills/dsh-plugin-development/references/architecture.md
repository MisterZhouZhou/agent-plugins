# DSH 插件架构

本文件用于在开始写代码前确定插件形态、运行边界、跨端协议和生命周期责任。默认遵循“最小可行形态”：只声明并实现需求真正需要的半区。

## 形态决策

- **Host-only**：只提供命令、工具、任务、进程、文件系统、服务或其他无 UI 能力。
- **Client-only**：只提供页面、Slot、设置卡、浏览器事件或其他 Web 交互；仍可保留一个无业务逻辑的 Node 入口供 bundle roster 加载。
- **Full-stack**：浏览器需要调用 Host，或 Host 状态需要驱动 Web UI；必须建立明确的 Core 协议。

形态确定后再选能力类型：普通 Plugin 负责生命周期和业务逻辑；Tool 是被模型调用的 Host 能力，必须依赖 `tools`；Service/Provider/Consumer 和 LLM Adapter 见对应专题。

判断顺序：

1. 需求是否需要访问 DSH 工作区、运行命令、管理进程、保存服务端状态或使用 Host 权限？需要则包含 Host。
2. 需求是否需要页面、Slot、设置卡或浏览器交互？需要则包含 Client。
3. 两者都不需要时，先重新审查需求边界，不要为了“完整”而加入空壳半区。

默认选择最小形态：没有浏览器需求时不声明 `dsh.client`；没有 Host 业务时，Node 入口只承担 Cordis 插件身份和加载契约，不承载无关业务逻辑。

## Host 导出形态决策

- **函数形式**：默认；适合 Tool、事件监听和简单功能。
- **对象形式**：与函数形式基本等价，只是把 `name`、`inject`、`apply` 等集中到对象中。
- **类形式**：用于继承 `Service` 并向其他插件提供公共、有状态或可替换能力。

导出形态与 Host-only/Client-only/Full-stack 是两个维度：前者决定 Host 模块怎样被 Cordis 加载，后者决定包包含哪些运行时入口。详见 `host-development.md`。

## 边界

### Host

Host 运行在 Node/Cordis 宿主，负责：

- 权限敏感操作、持久化、工作区和运行时文件访问。
- 子进程、任务调度、网络代理和服务端状态。
- Cordis 服务、事件监听和插件配置的生命周期管理。

Host 必须在卸载时释放事件、定时器、子进程、文件监听和服务资源。运行时代码通过公开 SDK 访问 DSH 能力，不深度导入 DSH 内部模块。

### Client

Client 运行在 DSH Web 浏览器环境，负责：

- 页面、Slot、设置 UI、用户交互和浏览器端状态。
- 调用公开的跨端服务或发送已定义的请求、响应和事件。
- 在卸载或热重载时移除页面、事件、样式和其他注册。

Client 不得依赖 `node:*`、裸文件系统 API、宿主绝对路径、服务端密钥或仅在 Host 存在的单例对象。浏览器 bundle 的依赖边界必须以执行时确认的宿主 ModuleLoader 平台模块为准。

### Core

Core 只放跨端可复用的纯内容：

- TypeScript 类型、请求/响应 DTO 和协议常量。
- 运行时 schema、编解码器和事件名。
- 不依赖环境的纯函数、默认值和错误码。

Core 不得引用 DOM、Node API、文件系统、进程、浏览器全局对象或带单例身份的运行时对象。Core 的导出应能被 Host 测试和 Client 测试分别加载。

## 跨端协议

Full-stack 插件先定义协议，再实现两端。协议至少应明确：

- 稳定的命名空间，例如 `dsh:<plugin>:<operation>`。
- 请求、响应、事件的名称、字段、可选性、版本策略和错误码。
- 超时、取消、重复请求、未知操作和旧 Client/Host 的处理方式。
- 哪些字段允许传输，哪些数据必须在 Host 留存。

所有跨端消息都必须可序列化并接受运行时校验。插件若声明 `Config` 类型，必须另有同名运行时 Schemastery schema，让 Cordis 在加载时校验配置并填充默认值。Host 只返回用户可理解的错误码和安全消息，不向 Client 发送堆栈、密钥、内部对象或本机绝对路径。协议演进时优先增加可选字段或新操作；破坏性变更必须附带兼容或迁移说明。

## 生命周期

所有注册都应有对应清理路径：

- 优先使用 Cordis 的 effect/dispose 机制管理 Host 事件、定时器、子进程和文件监听。
- Client 页面、Slot、设置、事件和样式都要记录注销方式；不能只依赖整页刷新清理。
- 热重载后不得重复注册页面、事件、定时器或服务。
- 错误路径也必须执行清理；初始化失败不能留下半初始化资源。

实现前把每个外部资源列成“创建点—使用点—清理点”，并为关键清理路径编写测试。
