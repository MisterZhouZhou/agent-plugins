# 语雀前端需求的可替换 Mock 策略设计

## 背景

`yuque-develop-requirements` 当前会在前端 PRD 缺少真实接口文档时使用 `<接口路径>` 等占位，并提示“暂时定一个，返回假数据”。该表达能说明先使用假数据，但不足以约束开发实现为后续真实接口接入保留清晰边界，容易出现页面内写死数据、散落环境判断或替换真实接口时重写页面逻辑的问题。

## 目标

当 PRD 没有真实接口文档时，生成的前端技术文档应同时表达：

1. 可以先使用 Mock 数据推进页面开发。
2. Mock 必须通过独立 API 请求层提供，页面和组件不得直接写死业务数据。
3. 页面仍按真实异步请求流程处理 loading、成功、空数据和失败状态。
4. 后续接入真实接口时，原则上仅替换 API 实现、请求参数和响应字段适配，不修改页面交互与业务流程。
5. 未确认的接口路径和字段继续使用占位标签，不臆造真实后端契约。

## 范围

更新以下文件：

- `skills/yuque-develop-requirements/SKILL.md`
- `skills/yuque-develop-requirements/assets/frontend_requirement_template.md`
- `skills/yuque-develop-requirements/references/usage_guide.md`

不修改后端需求模板，也不改变“接口详情缺失属于提醒类、默认不阻塞技术文档产出”的现有判断。

## 设计

### Skill 行为规则

在前端信息提炼和接口占位规则中明确：

- 根据页面动作识别查询、详情、提交、删除、上传等接口调用场景。
- 真实接口文档缺失时，使用 `<接口路径>`、`<请求参数>`、`<响应字段>`、`<字段名>` 等占位标签。
- Mock 实现放在独立 API 请求层，页面和组件只调用统一 API 方法。
- 禁止在页面或组件内直接写死 Mock 业务数据，禁止让 Mock 开关散落在业务代码中。
- Mock 与真实请求保持一致的 Promise 或异步调用形式。
- 页面按真实请求流程处理 loading、成功、空数据和失败状态。
- 后续接入真实接口时，以仅调整 API 实现及字段适配为目标，不修改页面交互和业务流程。

### 前端模板

新增“接口与 Mock 约束”章节，作为生成文档的全局要求。页面和组件中的接口示例不再只写“暂时定一个，返回假数据”，而是明确：

- 真实接口未提供；
- 先在独立 API 层提供 Mock；
- 页面通过统一 API 方法调用；
- 后续仅替换 API 实现和字段映射。

### 使用说明

将“没有接口信息时写暂无”的旧说明调整为当前实际策略：

- 不猜测正式接口路径和字段；
- 生成接口占位和可替换 Mock 约束；
- 允许前端先开发；
- 真实接口到位后尽量只替换 API 层和字段适配。

## 兼容性与非目标

- 保留现有占位标签语义。
- 若用户在参考上下文中明确提供真实接口文档或命名规则，继续优先使用真实信息，不启用缺失接口的 Mock 兜底描述。
- 不规定具体 Mock 工具、目录名或框架，避免与目标项目技术栈冲突。
- 不新增接口确认问答，也不把接口路径和字段缺失升级为阻塞问题。

## 验收标准

1. 三个目标文件对“先 Mock、后续可替换”的描述一致。
2. 前端模板明确禁止页面和组件直接写死 Mock 数据。
3. 前端模板要求 Mock 采用真实异步调用边界，并处理 loading、成功、空数据和失败状态。
4. Skill 明确后续真实接口接入原则上只修改 API 实现和字段适配。
5. 使用说明不再声称前端接口缺失时仅输出“暂无”。
6. `<接口路径>`、`<请求参数>`、`<响应字段>`、`<字段名>` 等占位规则继续保留。
7. 后端模板没有改动。
8. `git diff --check` 通过，最终差异不包含无关文件修改。
